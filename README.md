# StayWhereWindowsAre

让窗口待在它该在的地方。

macOS 在重启、系统更新、插拔显示器、睡眠唤醒之后经常把窗口布局打乱。StayWhereWindowsAre 常驻菜单栏，持续记住每个应用窗口的**位置、大小、所在显示器和所在桌面（Space）**，在下面这些时刻自动把窗口放回原处：

- **应用重新打开**：观察应用新出现的窗口，逐个放回上次的位置和桌面
- **开机 / 登录**：等系统和应用把窗口恢复出来后统一归位
- **插拔显示器**：每种显示器组合各自记忆一份布局，换回某个组合时自动还原
- **睡眠唤醒**：修正唤醒时被系统挪乱的窗口

另外还有：现代化的设置界面（概览、通用、恢复、应用、布局与快照、权限、诊断、日志）、菜单栏面板、登录时自动启动、手动/自动快照与“恢复前的布局”撤销、按应用排除、自检。

## 安装

需要 Xcode（工程用 [XcodeGen](https://github.com/yonaskolb/XcodeGen) 生成，`project.yml` 是工程的唯一来源）。

```bash
scripts/build.sh --install --open
```

首次启动时：

1. 系统会提示授予**辅助功能**权限：系统设置 › 隐私与安全性 › 辅助功能，打开 StayWhereWindowsAre 的开关。授权后 App 会自动开始工作，无需重启。
2. App 会自动注册为**登录项**（可在“通用”页关闭）。
3. 菜单栏出现窗口图标，点击可以手动恢复、保存快照、暂停记录或打开设置。

> 自己编译的 App 是 ad-hoc 签名，**每次重新编译安装后签名都会变化，系统会让旧授权失效**。这时在“权限”页点“重置授权记录”，再重新打开开关即可。如果有 Apple Development 证书，可以用 `SIGN_IDENTITY="Apple Development: …" DEVELOPMENT_TEAM=… scripts/build.sh --install` 签名，授权就能在重新编译后保留。

## 恢复到“原来的桌面”是怎么做到的

macOS 14.5 起，系统不再允许第三方程序直接把**其他应用**的窗口移到另一个桌面（`SLSMoveWindowsToManagedSpace` 等私有接口对别人的窗口静默失效；在本机 macOS 27 上实测确认）。StayWhereWindowsAre 利用了两个实测成立的系统行为：

1. 窗口被移动到**另一台显示器**上时，会落到那台显示器**当前正在显示的桌面**；
2. 程序可以把**自己的**窗口移到任意桌面，激活它时系统会切换过去。

因此恢复一个窗口到“显示器 D 的桌面 T”时：先把 D 切换到 T（把自己的透明锚点窗口放到 T 并激活；不行时改用调度中心快捷键“切换到桌面 N”或“⌃←/⌃→”），再把窗口放到 D 上；如果窗口本来就在 D 的另一个桌面，就先把它临时停到另一台显示器，再放回来。**只有一台显示器时**无处中转，改为模拟“按住窗口标题栏 + 切换桌面”的拖拽（可在“恢复”页关闭）。每一步都会读回窗口服务器的状态核对结果，失败就换下一种方式；恢复结束后会切回你原来所在的桌面。

因为要切换桌面，跨桌面恢复时屏幕会短暂切换。不同 Mac 上哪种切换方式有效可能不同，**建议首次授权后在“诊断”页运行一次自检**，App 会据此自动调整尝试顺序。

## 记录与匹配

- 每隔几秒比较一次窗口服务器的状态（不读取窗口内容），有变化才通过辅助功能接口读取窗口详情；窗口移动、新建时也会通过辅助功能通知及时记录。
- 系统接口只返回当前桌面的窗口，其他桌面上的窗口通过按元素编号探测的方式找到（可在“通用”页关闭）。
- 显示器变化、睡眠、锁屏、切换用户、恢复期间、以及 5 分钟无操作时暂停记录，避免把被打乱的布局存成“原来的样子”。
- 同一次登录内按窗口编号精确匹配；应用重启或开机后按标题相似度、大小和窗口顺序匹配。应用刚启动时会等窗口标题稳定后再匹配，避免把“新标签页”之类的临时标题配错。
- 布局保存在 `~/Library/Application Support/StayWhereWindowsAre/`（`layouts.json` 当前布局，`history.json` 快照），日志在 `~/Library/Logs/StayWhereWindowsAre.log`。不联网，不需要屏幕录制权限。

## 已知限制

- 全屏窗口和分屏窗口不处理（它们各自占用独立的全屏空间，由系统管理）。
- 少数不支持辅助功能接口的应用（部分 Java/游戏窗口）无法移动。
- 使用了未公开的系统接口，未来 macOS 版本可能失效；App 在运行时查找这些接口，缺失时会自动降级（“诊断”页可以看到可用情况）。
- 开机后应用重新创建的窗口只能按标题等特征匹配，标题完全变化且有多个同尺寸窗口时可能配对不准。

## 开发

```bash
xcodegen generate                       # 修改 project.yml 或增删文件后
open StayWhereWindowsAre.xcodeproj
xcodebuild test -project StayWhereWindowsAre.xcodeproj -scheme StayWhereWindowsAre -destination 'platform=macOS'
swift scripts/make-icon.swift           # 重新生成 App 图标
```

Debug 构建支持两个调试开关：

- `SWWA_SANDBOX_DIR=/tmp/x <App>/Contents/MacOS/StayWhereWindowsAre`：使用独立的数据目录和设置运行，不弹授权框、不注册登录项。
- `<App>/Contents/MacOS/StayWhereWindowsAre --snapshot-ui /tmp/ui`：把菜单栏面板和每个设置页渲染成 PNG（浅色/深色）。

代码结构：

| 目录 | 内容 |
| --- | --- |
| `Sources/Core` | 私有接口封装、辅助功能、窗口目录、记录、匹配、恢复计划与执行、桌面切换、事件监听、存储、设置 |
| `Sources/App` | 协调中枢 `AppModel`（冻结状态机、触发器、启动观察）、自检、入口 |
| `Sources/UI` | 菜单栏面板与设置窗口 |
| `Tests` | 匹配、坐标换算、恢复计划、桌面解析、存储的单元测试 |
